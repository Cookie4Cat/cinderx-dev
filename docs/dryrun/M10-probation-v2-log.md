## 三、A2：试用期冻结二审——三代机制、六个失效模式（阴性）

M9 一审判决"计时试用此粒度不可行"，本轮以新证据（A1 全负矩阵
意味着 per-code 贪心不再有 deltablue 式全局错配之忧）重审，
三代机制全部以插桩计数定界后仍不可用：

- **v1（原型直启）**：margin=125 冻结零触发（家族单体劣化 5-15%
  低于余量，弥散性坐实）；margin=100 deepcopy +7% 但
  **richards −28%**——插桩显示冻结数仅 1，伤害并非误冻；
- **v2（排队授予替换令牌轮询）**：v1 的 ctl==2 等待者每调用 CAS
  同一全局缓存线；改静默排队+链式授予后病理不变。插桩定罪：
  **首个授予者是编译后再也不被调用的死 code，串行链永久卡死**，
  63 个排队者全程包装态；
- **v3（按调用报名替代按编译报名）**：死 code 不再占位，但队列
  仍被启动期温函数占满（最先越过 auto=4 阈值的 import/harness
  机械），基准热核心反被容量帽挡在试用之外；richards 仍 −27%。

**根因（本轮新知，超出 M9 一审）**：插桩计数 pending_compiled_
calls=1.4 万 × 每次 ~1µs ≈ richards 全部 15ms 损失——被调方
处于包装态期间，其**全部调用方的特化调用位点连环
DEOPT/再特化抖动**（CALL_PY_EXACT_ARGS 按 [P4] 判据 DEOPT →
自适应计数耗尽 → 重特化 → 再 DEOPT 循环），成本记在调用方
call site 上、与被调方被调次数同阶。串行队列使该税必然贯穿整个
试用时代；缩短时代（死线/容量帽）与消除轮询只能缓解常数，
消除不了结构。叠加余量两难（125 冻不动/100 守护组重伤），
**per-code 计时试用在 3.11 auto-JIT 架构上判为结构性不可行**，
旋钮保留为研究态（默认 0）。
