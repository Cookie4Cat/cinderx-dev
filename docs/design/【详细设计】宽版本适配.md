# 详细设计说明书

## Keywords 关键词

CinderX, CPython, patch 兼容, fat wheel, wheel, manylinux, native variant, UpstreamBorrow

## Abstract 摘要

本文档描述 CinderX 在 Linux aarch64 平台上支持 CPython 3.14.0 至 3.14.3 的单 wheel 发布方案。

方案采用 fat wheel 形态：分别使用 CPython 3.14.0、3.14.1、3.14.2、3.14.3 构建四个 native variant，并将它们合并到一个 `cp314-cp314` wheel 中。运行时由顶层 `_cinderx.py` loader 根据 `sys.version_info.micro` 选择对应的 native extension。

## List of abbreviations 缩略语清单

| 缩略语 | 全称 | 说明 |
|--------|------|------|
| ABI | Application Binary Interface | 二进制接口 |
| CI | Continuous Integration | 持续集成 |
| whl | wheel | Python 二进制分发包格式 |
| micro | Micro version | Python 版本号第三位，如 3.14.2 |
| SOABI | Shared Object ABI tag | CPython 扩展模块 ABI 标识 |
| native variant | Native binary variant | fat wheel 中针对某个 CPython micro 版本构建的 `_cinderx` native 扩展 |
| UpstreamBorrow | Upstream code borrowing tool | CinderX 从 CPython 源码同步 private implementation 的工具链 |

## 简介

CinderX 是 CPython native extension，会使用 CPython internal header、private runtime state、interpreter loop、opcode metadata 和 generated cases。Python wheel tag 只表达 minor 级别 ABI，例如 `cp314-cp314`，不能表达 CPython 3.14 各 patch 版本的内部差异。

本方案将 patch 兼容性收敛到构建和打包流程中：每个支持的 CPython micro 版本对应一个 native variant，最终对用户发布一个 wheel。

支持范围：

```text
CPython 3.14.0
CPython 3.14.1
CPython 3.14.2
CPython 3.14.3
Linux aarch64 manylinux
```

发布 wheel 的安装范围：

```text
Requires-Python: >=3.14,<3.14.4
```

## 实现设计：CinderX 跨 patch 版本兼容

### 实现概述

方案分为四层：

**构建层**：使用固定 builder image，镜像内提供 CPython 3.14.0 至 3.14.3 四套源码构建 runtime。

**打包层**：每套 runtime 构建一个 ordinary wheel，经 `auditwheel repair` 后，由 repack 脚本合并为一个 fat wheel。

**安装层**：fat wheel 保持 `cp314-cp314` tag，并通过 `Requires-Python: >=3.14,<3.14.4` 限定安装范围。

**运行时层**：顶层 `_cinderx.py` loader 根据 CPython micro 版本加载对应 native variant。

### 关键算法与流程

产品化入口：

```bash
python3 ci_pipeline/build_cp314_manylinux_fat_wheel.py
```

核心流程：

```text
1. 使用 builder image 中的 CPython 3.14.0/1/2/3 分别构建 ordinary wheel。
2. 对四个 ordinary wheel 执行 auditwheel repair。
3. 调用 build_cp314_fat_wheel.py 合并 repaired wheel。
4. 将最终 fat wheel 写入 wheelhouse/。
5. 检查 wheel 结构，并默认执行 import smoke。
```

输出 wheel 布局：

```text
_cinderx.py
cinderx/_native/fat_wheel.json
cinderx/_native/py314_0/_cinderx_3140*.so
cinderx/_native/py314_1/_cinderx_3141*.so
cinderx/_native/py314_2/_cinderx_3142*.so
cinderx/_native/py314_3/_cinderx_3143*.so
```

关键约束：

```text
1. builder runtime 必须通过 check-cpython-314-builds。
2. 四个输入 wheel 的 distribution/version/python tag/abi tag/platform tag 必须一致。
3. 输出 wheel 不保留顶层 _cinderx*.so，只保留 _cinderx.py loader。
4. 输出 metadata 必须包含 Requires-Python: >=3.14,<3.14.4。
5. RECORD 必须重新生成。
```

运行时选择：

```text
3.14.0 -> cinderx/_native/py314_0/
3.14.1 -> cinderx/_native/py314_1/
3.14.2 -> cinderx/_native/py314_2/
3.14.3 -> cinderx/_native/py314_3/
```

非 CPython 3.14 或未列入支持矩阵的 micro 版本会在 import 阶段抛出 `ImportError`。

### UpstreamBorrow 原理、规格和同步方案

#### 原理

CinderX 会使用部分 CPython private implementation。UpstreamBorrow 用于从 CPython 源码中自动抽取这些实现，并编译进 CinderX 的 `borrowed` library。

该机制的目的：

```text
1. 保留 borrowed code 的来源文件和符号信息。
2. 避免手工复制大段 CPython 源码。
3. 让 private implementation 的同步过程可审计、可复现。
```

#### 规格

核心文件：

```text
cinderx/UpstreamBorrow/UpstreamBorrow.py
cinderx/UpstreamBorrow/borrowed-3.14.c.template
cinderx/UpstreamBorrow/borrowed-3.14.gen_cached.c
cinderx/UpstreamBorrow/borrowed.h
cinderx/UpstreamBorrow/callgraph.py
cinderx/UpstreamBorrow/find_missing.py
```

构建时使用已生成的 cached 文件：

```text
cinderx/UpstreamBorrow/borrowed-<PY_VERSION>.gen_cached.c
```

template 中通过 `// @Borrow ...` directive 描述需要从 CPython 源码抽取的函数、变量、typedef、struct、enum 或预处理指令。`borrowed.h` 负责必要的 symbol rename、prototype 和版本条件。

#### 同步方案

更新 borrowed code 时：

```text
1. 定位需要同步的 CPython private symbol 或源码片段。
2. 更新对应版本的 borrowed template。
3. 重新生成 borrowed-*.gen_cached.c。
4. 检查 generated diff，确认来源清晰且变更最小。
5. 运行构建、test_cinderx、Lib/test 和 wheel_compat。
```

UpstreamBorrow 负责源码同步和 private symbol 可维护性；patch 版本运行时选择由 fat wheel native variant 负责。

### 行为模型

#### 正常流程

```text
1. 构建 builder image。
2. 使用四套 CPython runtime 构建 ordinary wheel。
3. auditwheel repair。
4. repack 成 fat wheel。
5. fat wheel 输出到 wheelhouse/。
6. 用户 pip install。
7. import _cinderx 时 loader 选择对应 native variant。
```

#### 异常流程

| 场景 | 行为 |
|------|------|
| Python 版本不在支持范围 | pip 拒绝安装，或 loader 抛出 ImportError |
| 缺失 native variant | loader 抛出 ImportError |
| builder runtime 配置不符合要求 | 构建前置检查失败 |
| ordinary wheel 构建失败 | 打包流程失败并保留日志 |
| auditwheel repair 失败 | 打包流程失败并保留日志 |
| repack 输入 wheel 不一致 | repack 脚本失败 |

### 接口设计

#### 打包脚本接口

```bash
python3 ci_pipeline/build_cp314_manylinux_fat_wheel.py \
  [--source-dir SOURCE_DIR] \
  [--output-dir OUTPUT_DIR] \
  [--wheelhouse-dir WHEELHOUSE_DIR] \
  [--image IMAGE] \
  [--requires-python '>=3.14,<3.14.4'] \
  [--resume]
```

默认值：

```text
source-dir: 当前仓库根目录
output-dir: build/cp314-fat-wheel
wheelhouse-dir: <source-dir>/wheelhouse
image: cinderx-cp314-builder:manylinux_2_28_aarch64-20260519
requires-python: >=3.14,<3.14.4
```

#### wheel 兼容性 gate 接口

```bash
CINDERX_TEST_WHEEL=/path/to/fat.whl \
CINDERX_TEST_PYTHON=/root/opt/cpython-3.14.X/bin/python3.14 \
/root/opt/cpython-3.14.X/bin/python3.14 ci_pipeline/run_gate.py wheel_compat
```

`wheel_compat` 包含：

```text
setup_wheel
test_cinderx_wheel
lib_test_adaptive_aware_24
lib_test_official_skip_ok_26
```

### 代码实现要点

```text
1. 一个 native variant 只对应一个 CPython micro 版本。
2. fat wheel 顶层只保留 _cinderx.py，不保留 _cinderx*.so。
3. Requires-Python 固定为 >=3.14,<3.14.4。
4. 最终产物输出到 wheelhouse/。
5. 构建前必须运行 builder runtime 配置检查。
6. CI 必须验证已构建的 fat wheel。
```

## DFX分析

### 可靠性分析

发布候选 fat wheel 必须在 CPython 3.14.0、3.14.1、3.14.2、3.14.3 上分别运行 `wheel_compat`。

当前验证结果：

```text
3.14.0: Jobs 4/4 passed, Tests 826 passed, 60 skipped, 8 deselected
3.14.1: Jobs 4/4 passed, Tests 827 passed, 60 skipped, 8 deselected
3.14.2: Jobs 4/4 passed, Tests 827 passed, 60 skipped, 8 deselected
3.14.3: Jobs 4/4 passed, Tests 827 passed, 61 skipped, 8 deselected
```

新增 CPython patch 版本时，需要新增对应 native variant、更新 loader mapping、更新 `Requires-Python` 上界，并重新运行完整验证。

### 异常处理设计

| 异常场景 | 处理方式 |
|---------|----------|
| builder runtime 检查失败 | 阻塞构建 |
| ordinary wheel 构建失败 | 保留日志并终止 |
| auditwheel repair 失败 | 保留日志并终止 |
| fat wheel 结构检查失败 | 阻塞发布 |
| wheel_compat 失败 | 阻塞发布 |

### 性能分析

fat wheel 的额外运行时成本只发生在 `_cinderx` 首次 import 时。loader 选择 native variant 后，实际执行路径仍为对应 native extension。

构建默认开启 CinderX PGO/LTO，以保持发布 wheel 的 native 性能。

### 安全和韧性分析

`Requires-Python` 和 loader runtime guard 形成双层保护，防止未知 runtime 自动使用该 wheel。

`fat_wheel.json`、host build manifest、ordinary/repaired wheel sha256、builder image 信息和 CI 日志共同提供发布产物的可追溯性。
